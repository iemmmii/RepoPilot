# RepoPilot 产品说明

状态：设计草案 v0.2，2026-10-29。项目不设固定完成期限，按质量里程碑演进。

## 定位与目标用户

RepoPilot 将一条 GitHub Issue 转化为有代码依据的调查结论，并逐步提供复现证据、候选修复、回归验证和 PR 草稿。用户能查清每项验收条件是如何得到支持的，以及还有哪些未知项。

技术特色聚焦为：**修复结论有独立行为依据，证据依赖可以核查，输入改变后重新判断有效性，执行中断后可靠恢复。** 仍以解决 Issue 为产品入口，底层验证机制服务于真实修复工作。

首批用户假设：维护中小型 Python 项目的开发者，以及需要调查陌生项目问题的贡献者。真实痛点假设是：理解仓库耗时、复现信息不完整、难以判断 AI 修复是否可靠。此处是产品假设，尚未通过用户访谈验证。

## 核心用户任务

| 场景 | 用户要得到的结果 |
| --- | --- |
| 接到一个陌生 Issue | 涉及哪些文件和符号、判断依据、可能原因、候选测试方式 |
| 判断问题是否成立 | 在明确版本和环境下运行的复现步骤、目标失败与实际输出 |
| 尝试修复 | 独立副本中的修改、原始失败与修复后结果的对应关系 |
| 准备提交 | 验收覆盖表、风险与未知项、可审查 Diff、PR 标题与描述 |
| 运行中断或缺环境 | 已有成果仍在，用户补充信息后从合适阶段继续 |

| 维度 | 纳入 MVP | 后续再评估 |

## 差异化应当如何被证明

“三个角色”和“自动修改代码”是实现手段。作品最值得展示的是以下三件事：

1. **验收覆盖可追溯**：Issue 要求 → 验收项 → 测试/审查证据 → 结论，缺项明确显示。
2. **结论随适用条件变化**：候选代码、断言、环境或验收条件改变后，依赖它们的当前结论需要重新验证；保留历史结果及其上下文。
3. **失败也有价值**：未复现、依赖缺失、预算耗尽都留下可以接手的报告，恢复不会把未提交结果当成完成。
4. **完成判断由证据约束**：模型说完成后仍经过确定性检查、Oracle 审定和适用的独立审查；同时测量虚假成功、错误拒绝、真实修复率与成本。

这些是拟实现的产品价值，不声称具有市场唯一性。第一个可用闭环后就收集少量真实使用反馈，验证用户能否缩短调查或审阅时间；不等功能全部齐全才验证用途。

## 按质量推进的可交付层次

**调查与复现层**：报告、隔离复现、独立行为依据与真实证据，能单独帮助用户接手问题。

**可靠修复层**：受限修复、最小 Gate、证据失效、恢复与对照评估；先用受控补丁验证机制，再让模型生成候选。

**完整交付层**：独立审查、验收覆盖表、PR 草稿、多仓库真实案例和可浏览的证据报告。

层次通过验收后再扩大范围，具体顺序见[阶段路线](../03-plan/milestones.md)。每次运行的超时、调用和修复次数限制继续保留；项目期限无限不等于单次运行无限。

## 从第一天就保持的验收标准

- 调查报告中的代码引用包含仓库版本、路径、行号或符号；系统检查引用确实存在。
- 候选原因、候选命令与已经验证的事实明确区分。
- 只有存在与 Issue 行为匹配的失败断言，才能标为“已复现”；导入失败或安装失败只说明环境问题。
- 同一版本的复现测试在 base 失败、在 patch 通过，只能支持该行为在这组测试条件下被候选覆盖；还需核对 Oracle 与独立验收。
- 断言必须有明确需求依据和独立审定记录；模型自写测试即使前后对照通过，最多得到测试范围内的候选结论，不能自动推导需求已满足。
- 通过结论还需指定回归测试执行、验收项覆盖与审查结论；跳过、xfail、空测试不能充当通过证据。
- 用户可查看原始执行记录，报告不能只包含模型生成的摘要。
- 模型、工具或存储出错时保留已完成产物，并明确最后可靠阶段。
- 当前结论注明最近一次适用性检查时间和快照。静态报告是历史快照，不能在源码被修改后仍被当作当前结论。

## 标准演示故事

准备一个可控仓库：过期 Token 导致错误处理异常，预期返回 401。该故事是计划中的测试样例，当前尚未创建或执行。

1. 输入样例 Issue；报告定位到认证入口和错误处理位置，附代码依据。
2. 新建复现测试，在固定 base 上观察到与预期不符的状态码。
3. Coding Worker 在副本中生成候选修复。
4. 使用冻结的同一复现测试重新运行，追加正常 Token 的回归测试。
5. Review Worker 检查 Diff 和验收项，给出独立结论。
6. 导出报告与 PR 草稿；“生产环境已验证”仍显示未验证。

补充一个缺依赖案例，演示系统能诚实报告“环境受阻”。具体样例集合见[评估方案](../03-plan/evaluation.md)。

技术演示再覆盖：修改候选后撤销当前通过状态、替换为错误断言后阻止升级为需求已满足、在检查点提交前强制中断后正确恢复。只有实现并运行后才可作为项目成果或简历描述。

## 尚待用户偏好细化的事项

可用模型接口、运行预算、容器环境条件和首批真实样例仓库。时间不再是交付边界；根据真实失败决定深挖哪个 Harness 机制，避免只增加功能数量。
