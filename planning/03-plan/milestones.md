# 按质量里程碑推进的实施路线

版本：v0.2，2026-10-29。项目不设固定完成期限，不将阶段映射成一周。每阶段需要可运行产物与验收出口；单次 Run 仍有预算。实际状态见[进度台账](../04-progress/progress.md)。

## 任务连续性

原有 21 个任务 ID 保留，状态均为未开始；补充质量要求，新增 10 项任务，共 31 项。先完成窄范围真实闭环，再扩大样例和功能。规划变化不代表已经实现。

## M0：规划与技术假设基线

交付需求来源、选择性评审、产品边界、证据/Oracle/恢复/威胁设计、实施路线、评估与版本控制规范。出口是能区分用户要求、设计选择、待实验假设和实际能力，四周不再是约束。

## M1：运行基础与只读调查

目标：验证底座和环境，选择一个真实问题，交付有代码依据的调查报告。

| ID | 任务 | 交付与验证 |
| --- | --- | --- |
| P1-01 | 适配与环境小实验 | 核验 Linux 容器、底座 v2 模型/命令/退出/日志接口；选择一个真实 Issue 和已知 base，记录能否离线重跑 |
| P1-02 | 项目骨架与最小契约 | CLI、Issue/Run/Artifact、配置与依赖锁；声明预算和边界，不先创建完整空框架 |
| P1-03 | Issue 只读读取 | URL、本地 JSON、限流和错误分类；外部文本不能更改权限 |
| P1-04 | 仓库版本与检索 | 固定 base 与实际源码摘要；过滤、rg/AST、路径/符号检查；不通过 import 扫描 |
| P1-05 | RepoGuide 与调查报告 | 事实、假设、候选命令分开；Top-5 相关文件依据及固定版本产物 |
| P1-06 | 最小存储与 CLI 验收 | 单写入者、manifest、状态查询；fake Provider 测试与一个真实模型调查 |

出口：一个真实或来源明确的受控样例完成只读调查，引用存在且绑定版本。沙箱受阻时可先交付只读调查，不能退回宿主执行目标项目。

## M2：独立行为依据与最小验证闭环

目标：用同一问题的已知样例补丁跑通“需求 → Oracle → base 失败 → candidate 通过 → Gate”，不依赖模型先成功修复。

| ID | 任务 | 交付与验证 |
| --- | --- | --- |
| P2-01 | SandboxRunner 与权限 | 固定镜像、非特权、资源/网络边界、受限源码；执行威胁模型中的适用反例 |
| P2-02 | 可信命令证据 | 命令、时间、返回码、终止、日志及源码/套件/环境指纹；真实超时和中断记录 |
| P2-03 | 复现断言与冻结 | 固定 suite_hash；核对 base 目标失败，不把导入失败当复现 |
| P2-04 | 复现分类与报告 | reproduced、not_reproduced、environment_blocked、needs_human、unstable；保留依据和未知项 |
| P2-05 | 阶段恢复与初始评估 | 最小检查点、未提交结果隔离；3 个调优案例，开始记录指标 |
| P2-06 | Oracle 来源与独立审定 | 分开需求、断言和执行可信度；accepted/provisional/rejected 有依据；错误断言不因 fail/pass 获得成功 |
| P2-07 | 最小 Claim 与 Gate | 受控补丁的确定性判定；缺证据、空测试、跳过和 provisional Oracle 不支持完整成功 |
| P2-08 | 最小证据 DAG | 类型化节点/边、输入指纹、依赖合法性与版本绑定；JSON 和内存遍历即可 |

出口：一个补丁在明确 Oracle 和验证策略下完成真实对照；未复现、受阻、错误 Oracle 正确分类。自动审查未接入时明确采用的独立审定，不能伪造 Reviewer 通过。

## M3：模型修复、证据失效与恢复可靠性

目标：接入修复循环，使候选变动与中断不会产生虚假成功，用数据检查机制收益。

| ID | 任务 | 交付与验证 |
| --- | --- | --- |
| P3-01 | 副本与补丁管理 | managed worktree、受限源码与候选摘要；导出 Patch 检查路径及范围 |
| P3-02 | Coding Engine 适配 | 统一动作、退出、异常和预算；Submitted 不直接表示验收成功 |
| P3-03 | 冻结测试前后对照 | 同一 Oracle/suite、固定回归集；测试选择、跳过和内容变化可见 |
| P3-04 | 完整 Gate 与有限返工 | 扩展至 repair 范围；分开 candidate_verified/resolved_verified；总预算与修复次数共同约束 |
| P3-05 | 本地修复闭环 | 至少 2 个真实或受控 Bug 的模型补丁通过独立验收；失败同样保留 Diff 和原因 |
| P3-06 | 失效传播与当前结论撤销 | 处理候选、套件、环境、条件和策略变更；保留历史；在 status/resume/Gate 检测旧证据误复用 |
| P3-07 | 故障注入与恢复语义 | F01～F06 检查提交点、orphan、损坏、复用次数和预算；先保证进程中断恢复 |
| P3-08 | 核心机制首轮对照 | 固定底座与预算；Gate、失效、Oracle 反例及基础 Agent 对照；报告拒判和错误拒绝 |

出口：至少 2 个修复、1 个诚实未完成案例；修改候选后当前结论失效；F01/F03/F04 经真实 Runner 验证；收益和成本可解释。缺少这些证据时先修核心，不以增加 Worker 替代质量。

## M4：独立审查与完整交付

目标：补全产品链，提供可审阅的修复与验收成果。

| ID | 任务 | 交付与验证 |
| --- | --- | --- |
| P4-01 | PR Guardian | 新上下文、只读快照和结构化发现；受输入指纹与失效规则约束；不把隔离等同独立真值 |
| P4-02 | 验收覆盖表 | 来源、Oracle、Claim、证据、适用性和未知项；必要条件不为通过而删减 |
| P4-03 | 统一报告与 PR 草稿 | 证据链、前后对照、失效原因、快照及核验时间；本地 PR 草稿 |
| P4-04 | 全链路对照与失败分析 | 扩展 M3 对照至审查流程；保留全部尝试和外部验收，检验独立上下文的实际收益 |
| P4-05 | 可重复技术演示 | 成功、修改候选、错误 Oracle、提交前中断；记录版本、命令、局限和自研源码落点 |

出口：完整报告能回答结论的支持来源；审查收益经验证或明确未确定，不能因加入审查模型就声称更可靠。

## M5：真实有效性与产品成熟度

目标：验证可控样例中的收益能否迁移到真实项目，用结果决定后续范围。

| ID | 任务 | 交付与验证 |
| --- | --- | --- |
| P5-01 | 多仓库真实 Issue 集 | 从早期样例扩至至少 3 个小型 Python 仓库、约 5～10 个准入 Issue；冻结协议，记录排除与受阻 |
| P5-02 | 可重跑评估与长期回归 | 版本化样例清单、独立 judge、依赖/Prompt/策略及逐次结果；关键反例与恢复测试进入实际 CI |
| P5-03 | 离线证据浏览报告 | 契约稳定后增加静态/离线 HTML；转义、脱敏、无隐式执行，复用 CLI 事实模型 |
| P5-04 | 用户价值与技术复盘 | 实际使用或经授权的反馈验证调查/审查成本；整理源码、故障证据和实测数据形成可核查作品说明 |

出口：真实集逐案例结果完整，包含成功、失败、拒判和成本；效果不足时继续迭代，不改分母或只留成功任务。样例数量是初始协议，不代表统计充分。

## 实施依赖与范围边界

先固定输入和可信执行，再讨论图；先审定 Oracle，再解释修复正确性；先验证失效与恢复，再扩大缓存/并发。评估始于 M2，真实样例选于 M1，展示由实际数据生成。

不限期限仍暂缓图数据库、向量库、常驻 Agent 团队、分布式队列、多租户、计费与自动远程发布。只有真实问题与实验收益支持时才扩展。

## 下一次实施的最小工作单元

执行 P1-01，确认沙箱、一个模型接口、底座适配和一个真实样例，记录成功/失败条件及只读降级路径。随后完成 P1-02～P1-06 调查闭环，再用同一问题的已知补丁进入 M2。
