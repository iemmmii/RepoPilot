# M3 首个实施单元：受管候选与补丁边界

日期：2026-10-30。关联 P3-01，提供 P3-02/P3-06 所需的版本与失效基础。

## 问题与取舍

M2 验证的是调用者提供的 Git 提交，尚无安全生成候选的入口。直接让模型修改用户工作区，会混入未提交改动，也可能修改测试、密钥或 Git 配置。先把“提出修改”与“接受修改”分开。

采用 `git worktree add --detach --no-checkout` 注册受管工作树，但不运行目标仓库的 checkout、过滤器、hooks、构建或 Python 导入。源码来自既有有界 Git 对象物化器。Git 元数据仅供控制器使用，未来 Worker 只能获得受限源码和类型化动作接口。

首版修改协议仅替换已有、允许的 UTF-8 Python 实现文件；禁止新增/删除、测试、配置、凭据及链接。每个修改携带原内容 SHA-256；整体校验通过才写入。更广泛的合法修复留待有需求和测试时扩展，不通过默认放开权限实现。

候选提交通过独立 index、原始 blob、write-tree/commit-tree 构造，绕过 .gitattributes 的 clean/smudge 过滤。父提交固定，不修改用户分支、index 或工作区。保留完整 Git 树中未交付的文件，运行沙箱仍只获得有界快照。

## 交付

- `domain/patches.py`：有限修改协议、候选清单与内容指纹。
- `repository/candidates.py`：创建、校验、应用、导出与受管工作树清理；路径、范围和陈旧原文检查。
- CLI：候选创建、应用 JSON 提案、状态/导出；不执行模型生成的 shell。
- 补丁、修改清单、base/candidate SHA 与摘要可审计；候选一经变化，旧导出的验收绑定不再代表当前候选。

## 验收协议

1. 脏用户工作区及 index 保持逐字节不变；受管候选只读固定 base。
2. 遍历、大小写歧义、链接/Windows junction、测试及配置修改、原文摘要不匹配、语法错误均拒绝，合法批次不被部分应用。
3. 目标 hooks 和 .gitattributes 过滤器设置为可观察陷阱，候选创建/提交/导出不触发它们。
4. 导出提交可交给现有 verify-candidate；原有 base 失败、候选通过，证据仍由 Docker Runner 产生。
5. 故障与无效提案保留明确原因，不把候选生成或 Git 提交等同修复成功。

## 后续依赖

本单元之后接 mini-swe-agent 2.4.6 的生产适配器，沿用已验证的 Model/Environment 协议；不得用自研无限 shell Agent 代替底座。冻结测试与独立 Oracle 不放进可写候选。P3 的模型修复、完整失效和对照评估仍需单独验收。
