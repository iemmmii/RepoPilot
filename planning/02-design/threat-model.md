# 威胁模型与最小安全验证

状态：设计草案 v0.2。范围为开发者本地使用、受控公开 Python 样例；任意恶意仓库的公开多租户托管服务不在首版能力范围。

## 资产、对手和信任边界

需要保护宿主文件与凭据、控制面权限、不可覆盖的运行证据、冻结 Oracle、资源预算及用户对验收结论的判断。

不可信输入包括 Issue/评论、仓库文字、生成的补丁和测试、依赖安装脚本、命令输出，以及 Worker 返回的 JSON。模型不能通过输出“新系统规则”更改权限。

信任根是受用户控制的 Orchestrator、Runner、输入/策略校验和存储边界。容器和只读挂载是约束手段，执行器记录“哪个进程运行并返回什么”，不能单独证明仓库代码或测试的语义真实。

## 具体攻击面

| ID | 攻击或失败路径 | 控制与拒绝规则 | 后续验收反例 |
| --- | --- | --- | --- |
| T01 | Issue/README 指示忽略任务、读取密钥或发布远程内容 | 外部文本仅作数据；权限由控制面配置；不给远程写工具 | 注入文本不能改变配置或调用禁用工具 |
| T02 | 容器访问宿主 HOME、Docker socket、共享 Git 元数据 | 只提供受限源码副本；不传递凭据，不挂载控制面目录；非特权 | 在受控环境内尝试读取模拟宿主秘密路径，必须失败 |
| T03 | Patch、归档或符号链接穿越工作根目录 | 规范化与解析真实路径；拒绝越界、绝对路径及不支持的链接；导入前后核验 | 包含 `../`、驱动器路径或越界链接的补丁/导出被拒绝 |
| T04 | Worker 伪造日志、证据 ID 或修改 manifest | 可信 Runner 登记证据；控制面独占写入；校验摘要、Run 和 attempt | 假 TestResult、跨 Run 引用、篡改 Artifact 不能支持 Claim |
| T05 | 删除测试、加入 skip、改弱断言或配置 | 控制面保存冻结套件和测试选择；独立 judge 环境；Oracle 审定 | 候选“全绿”但必要断言未执行仍拒绝验收 |
| T06 | 无限循环、巨量日志、超时和子进程残留 | CPU/内存/墙钟/调用/输出限制；按容器生命周期清理 | 限制触发后保存停止原因，不能标为成功 |
| T07 | 安装脚本或网络依赖带来未知行为 | 依赖准备单独受控；固定镜像和锁；验证阶段断网 | 断网或依赖变化明确受阻，不能悄悄沿用其他环境结果 |
| T08 | 历史静态报告或缓存被当作当前通过 | 输出快照/时间；status、resume、Gate 重新检查依赖 | 改候选或环境后，当前通过状态失效，旧页面仍标为历史 |

所有“拒绝”需要结构化原因和可查看的记录。对于能力/配置无法落实的边界，报告 environment_blocked 或 needs_human，不退回宿主执行不可信项目。

## Oracle 与隐藏测试的限制

Coding Worker 与 judge 分离，隐藏断言不进入修复上下文，也不挂载到 Coding 环境。测试由控制面按固定版本送入独立的干净验证环境。

这种隔离防止常规工作流中随意改测试，不保证恶意代码不能在执行时观察测试输入、篡改同一解释器或伪装结果。因此“隐藏”不等于绝对保密，不能据此为任意恶意仓库的修复正确性背书。

若目标仓库表现出主动规避验收、动态篡改测试工具或未声明的外部副作用，首版停止自动成功声明，记录限制并交由人工处理。更强的对抗式 judge 属于单独研究范围。

## 发布与导出

仅导出必要、脱敏的报告；不默认发布原始日志、个人对话、环境变量或完整 API 响应。离线 HTML 将日志/Issue 内容按文本转义，不直接运行仓库提供的 HTML 或脚本。

本项目 Git 上传与 RepoPilot 产品的远程写工具是两件不同的事：当前已上传项目规划，不代表未来 Agent 获得 GitHub 发布权限。

对应任务：P1-01、P2-01、P2-02、P2-07、P3-04、P3-06、P5-03。测试场景见[评估方案](../03-plan/evaluation.md)。
